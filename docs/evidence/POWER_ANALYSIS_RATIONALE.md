# Prospective Power Analysis Rationale

## Purpose

This document records the prospective sample-size and repeated-run rationale used before confirmatory interpretation.

## Design Basis

1. The confirmatory AI comparison uses repeated provider x prompt-condition cohorts rather than a single run.
2. The minimum confirmatory cohort count is 3 completed cohorts per arm.
3. The AI stability gate additionally expects arm spread to remain within 10 percentage points before cross-run claims are treated as confirmatory.
4. The primary AI endpoint requires both Holm-adjusted significance and a practical effect threshold of at least 3.0 percentage points.

## Sample-Size Rationale

1. A small repeated-run design is sufficient for dissertation-scale comparative evidence because the goal is controlled comparison, not population estimation.
2. The repeated-run threshold reduces the risk that a single unstable cohort drives the conclusion.
3. Balanced arm coverage is required so arm-to-arm contrasts remain interpretable.
4. The protocol treats under-powered or incomplete runs as exploratory rather than confirmatory.

## Prospective Blocking Rule

1. If any completed arm has fewer than 3 historical cohorts, confirmatory AI claims are blocked.
2. If the arm spread exceeds 10 percentage points, confirmatory AI claims are blocked.
3. If the primary endpoint fails Holm-adjusted significance or the practical effect threshold, confirmatory AI claims are blocked.

## Notes

1. This rationale is prospective and must be sealed before confirmatory release.
2. Any changes to the rationale require resealing and rerunning confirmatory checks.
